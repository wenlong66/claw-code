# TUI 增强计划 — Claw Code（`rusty-claude-cli`）

## 执行摘要

本计划对当前终端用户界面进行了全面分析，并提出分阶段增强方案，以将现有的 REPL/prompt CLI 转变为一个精致、现代的 TUI 体验——同时保留现有的清晰架构和测试覆盖。

---

## 1. 当前架构分析

### Crate 映射

| Crate | 用途 | 行数 | TUI 相关性 |
|---|---|---|---|
| `rusty-claude-cli` | 主二进制：REPL 循环、参数解析、渲染、API 桥接 | ~3,600 | **主要 TUI 表面** |
| `runtime` | 会话、对话循环、配置、权限、压缩 | ~5,300 | 提供数据/状态 |
| `api` | Anthropic HTTP 客户端 + SSE 流式输出 | ~1,500 | 提供流事件 |
| `commands` | Slash 命令元数据/解析/帮助 | ~470 | 驱动命令分发 |
| `tools` | 18 个内置工具实现 | ~3,500 | 工具执行显示 |

### 当前 TUI 组件

| 组件 | 文件 | 目前做什么 | 质量 |
|---|---|---|---|
| **输入** | `input.rs`（269 行） | 基于 `rustyline` 的行编辑器，支持 slash 命令 Tab 补全、Shift+Enter 换行、历史记录 | ✅ 稳定 |
| **渲染** | `render.rs`（641 行） | Markdown→终端渲染（标题、列表、表格、带 syntect 高亮的代码块、引用块），spinner 小部件 | ✅ 良好 |
| **App/REPL 循环** | `main.rs`（3,159 行） | 单体化的 `LiveCli` 结构体：REPL 循环、所有 slash 命令处理器、流式输出、工具调用显示、权限提示、会话管理 | ⚠️ 单体化 |

### 关键依赖

- **crossterm 0.28** —— 终端控制（光标、颜色、清屏）
- **pulldown-cmark 0.13** —— Markdown 解析
- **syntect 5** —— 语法高亮
- **rustyline 15** —— 带补全的行编辑
- **serde_json** —— 工具 I/O 格式化

### 优势

1. **清晰的渲染流水线**：Markdown 渲染具有良好的状态跟踪、表格渲染和代码高亮
2. **丰富的工具显示**：工具调用使用框线边框（`╭─ name ─╮`），结果显示 ✓/✗ 图标
3. **全面的 slash 命令**：15 个命令覆盖模型切换、权限、会话、配置、diff、导出
4. **会话管理**：完整的持久化、恢复、列表、切换、压缩
5. **权限提示**：对受限工具调用进行交互式 Y/N 许可
6. **充分的测试**：每个格式化函数、每条解析路径都有单元测试

### 缺点与缺口

1. **`main.rs` 是一个 3,159 行的单体**——所有 REPL 逻辑、格式化、API 桥接、会话管理和测试都在一个文件中
2. **没有 alternate-screen / 全屏布局**——一切都是内联滚动输出
3. **没有进度条**——只有一个 braille spinner；在生成过程中无法显示流式进度或 token 计数
4. **没有可视化 diff 渲染**——`/diff` 只是直接输出原始 git diff 文本
5. **流式输出没有语法高亮**——Markdown 渲染只应用于工具结果，而不是主 assistant 响应流
6. **没有状态栏 / HUD**——交互过程中看不到模型、token、会话信息
7. **没有图片/附件预览**——`SendUserMessage` 会解析附件，但从不展示它们
8. **流式输出按字符显示并带人工延迟**——`stream_markdown` 每个以空白分隔的 chunk 都会 sleep 8ms
9. **没有颜色主题自定义**——硬编码的 `ColorTheme::default()`
10. **没有尺寸变化处理**——没有对终端大小的感知，无法处理换行、截断或布局
11. **历史上的双 App 拆分**——仓库以前同时保留了一个独立的 `CliApp` 原型和 `LiveCli`；原型已移除，但单体化的 `main.rs` 仍然需要拆分
12. **长输出没有 pager**——`/status`、`/config`、`/memory` 可能溢出可视区域
13. **工具结果不可折叠**——大的 bash 输出会充斥屏幕
14. **没有思考/推理指示器**——当模型处于 “thinking” 模式时，没有视觉区分
15. **工具参数没有自动补全**——只有 slash 命令名称可以补全

## 2. 增强计划

### 阶段 0：结构清理（基础）

**目标**：拆分单体，移除死代码，为 TUI 工作建立模块结构。

| 任务 | 描述 | 工作量 |
|---|---|---|
| 0.1 | **将 `LiveCli` 提取到 `app.rs`** —— 把整个 `LiveCli` 结构体、其 impl，以及辅助函数（`format_*`、`render_*`、会话管理）从 `main.rs` 移到聚焦的模块中：`app.rs`（核心）、`format.rs`（报告格式化）、`session_manager.rs`（会话 CRUD） | M |
| 0.2 | **移除或合并遗留的 `CliApp`** —— 现有的 `app.rs` 里有一个未使用的 `CliApp`，它有自己基于 `ConversationClient` 的渲染。要么删除它，要么将其独有特性（流事件处理器模式）合并到活跃的 `LiveCli` 中 | S |
| 0.3 | **提取 `main.rs` 的参数解析** —— 当前的 `parse_args()` 是一个手写解析器，重复了基于 clap 的 `args.rs`。应统一使用手写解析器（它更完整），并把它移到 `args.rs`，或者彻底采用 clap | S |
| 0.4 | **创建 `tui/` 模块** —— 引入 `crates/rusty-claude-cli/src/tui/mod.rs` 作为所有新 TUI 组件的命名空间：`status_bar.rs`、`layout.rs`、`tool_panel.rs` 等 | S |

### 阶段 1：状态栏与实时 HUD

**目标**：在交互过程中持续显示信息。

| 任务 | 描述 | 工作量 |
|---|---|---|
| 1.1 | **终端尺寸感知状态行** —— 使用 `crossterm::terminal::size()` 渲染一个固定在底部的状态栏，显示：模型名称、权限模式、会话 ID、累计 token 计数、估算成本 | M |
| 1.2 | **实时 token 计数器** —— 在流式输出过程中，当 `AssistantEvent::Usage` 和 `AssistantEvent::TextDelta` 事件到达时，实时更新状态栏 | M |
| 1.3 | **轮次持续时间计时器** —— 显示当前轮次的已用时间（Config 工具中已经存在 `showTurnDuration` 配置，但尚未接入） | S |
| 1.4 | **Git 分支指示器** —— 在状态栏中显示当前 git 分支（已通过 `parse_git_status_metadata` 解析） | S |

### 阶段 2：增强型流式输出

**目标**：让主响应流在视觉上更丰富、更响应迅速。

| 任务 | 描述 | 工作量 |
|---|---|---|
| 2.1 | **实时 Markdown 渲染** —— 不再原样流式输出文本，而是缓冲 text delta 并在其到达时增量渲染 Markdown（标题检测、粗体/斜体、行内代码）。现有的 `TerminalRenderer::render_markdown` 可以改造成增量使用 | L |
| 2.2 | **思考指示器** —— 当启用扩展思考/推理时，显示一个不同的动画指示器（例如带脉冲点或不同 spinner 的 `🧠 Reasoning...`），而不是通用的 `🦀 Thinking...` | S |
| 2.3 | **流式进度条** —— 在 spinner 下方添加一个可选的水平进度指示器，显示大致完成度（基于 max_tokens 与当前 output_tokens） | M |
| 2.4 | **移除人工流延迟** —— 当前的 `stream_markdown` 每个 chunk 会 sleep 8ms。对于工具结果这没问题，但对主响应流应当立即显示或可配置 | S |

### 阶段 3：工具调用可视化

**目标**：让工具执行更易读、更易导航。

| 任务 | 描述 | 工作量 |
|---|---|---|
| 3.1 | **可折叠工具输出** —— 对于超过 N 行的工具结果（可配置，默认 15），显示带 `[+] Expand` 提示的摘要；按键后展开完整输出。最初可实现为截断，并在必要时回退为“完整输出已保存到文件” | M |
| 3.2 | **带语法高亮的工具结果** —— 当工具结果包含代码时（按工具名检测——`bash` stdout、`read_file` 内容、`REPL` 输出），应用 syntect 高亮，而不是按纯文本渲染 | M |
| 3.3 | **工具调用时间线** —— 对多工具轮次，在所有工具调用完成后显示一个紧凑摘要：`🔧 bash → ✓ | read_file → ✓ | edit_file → ✓（3 个工具，1.2s）` | S |
| 3.4 | **感知 diff 的 edit_file 显示** —— 当 `edit_file` 成功时，显示所做更改的彩色统一 diff，而不是只显示 `✓ edit_file: path` | M |
| 3.5 | **增强权限提示** —— 使用框线样式美化许可提示，给工具名称上色，并显示工具将要执行内容的一行摘要 | S |

### 阶段 4：增强 slash 命令与导航

**目标**：改进信息展示并补齐缺失功能。

| 任务 | 描述 | 工作量 |
|---|---|---|
| 4.1 | **彩色 `/diff` 输出** —— 解析 git diff，并像 `delta` 或 `diff-so-fancy` 一样用红/绿颜色渲染删除/新增内容 | M |
| 4.2 | **长输出 pager** —— 当 `/status`、`/config`、`/memory` 或 `/diff` 的输出长度超过终端高度时，使用内部 pager（用 j/k/q 滚动）或外部 `$PAGER` | M |
| 4.3 | **`/search` 命令** —— 添加一个按关键词搜索对话历史的新命令 | M |
| 4.4 | **`/undo` 命令** —— 通过恢复 `write_file`/`edit_file` 工具结果中的 `originalFile` 数据来撤销上一次文件编辑 | M |
| 4.5 | **交互式会话选择器** —— 将基于文本的 `/session list` 替换为可模糊过滤的交互式列表（上下箭头选择，回车切换） | L |
| 4.6 | **工具参数 Tab 补全** —— 扩展 `SlashCommandHelper`，为 `/export` 后的文件路径、`/model` 后的模型名称、`/session switch` 后的 session ID 提供补全 | M |

### 阶段 5：颜色主题与配置

**目标**：让用户可自定义视觉外观。

| 任务 | 描述 | 工作量 |
|---|---|---|
| 5.1 | **命名颜色主题** —— 添加 `dark`（当前默认）、`light`、`solarized`、`catppuccin` 主题。接入现有 `Config` 工具的 `theme` 设置 | M |
| 5.2 | **ANSI-256 / truecolor 检测** —— 检测终端能力并优雅降级（无颜色 → 16 色 → 256 色 → truecolor） | M |
| 5.3 | **可配置 spinner 样式** —— 允许在 braille dots、bar、moon phases 等样式之间选择 | S |
| 5.4 | **横幅定制** —— 让 ASCII 艺术横幅可选或可通过设置配置 | S |

### 阶段 6：全屏 TUI 模式（扩展）

**目标**：为高级用户提供可选的 alternate-screen 布局。

| 任务 | 描述 | 工作量 |
|---|---|---|
| 6.1 | **添加 `ratatui` 依赖** —— 引入 `ratatui`（终端 UI 框架）作为全屏模式的可选依赖 | S |
| 6.2 | **分栏布局** —— 上方面板：带回滚的对话；下方面板：输入区域；右侧边栏（可选）：工具状态/todo 列表 | XL |
| 6.3 | **可滚动对话视图** —— 使用 PgUp/PgDn 浏览历史消息，在对话中搜索 | L |
| 6.4 | **键盘快捷键面板** —— 显示 `?` 帮助覆盖层和所有按键绑定 | M |
| 6.5 | **鼠标支持** —— 点击展开工具结果、滚动对话、选择文本复制 | L |

## 3. 优先级建议

### 近期立即执行（高影响，中等工作量）

1. **阶段 0** —— 必要的清理。3,159 行的 `main.rs` 是首要维护风险，并阻碍干净的 TUI 添加。
2. **阶段 1.1–1.2** —— 带实时 token 的状态栏。这是影响最大的 UX 提升：用户总是想知道 token 使用情况。
3. **阶段 2.4** —— 移除人工延迟。工作量低，能立刻感知到改进。
4. **阶段 3.1** —— 可折叠工具输出。大型 bash 输出目前严重破坏可读性。

### 短期内（下一个迭代）

5. **阶段 2.1** —— 实时 Markdown 渲染。这会让核心交互感觉更精致。
6. **阶段 3.2** —— 带语法高亮的工具结果。
7. **阶段 3.4** —— 感知 diff 的 edit 显示。
8. **阶段 4.1** —— `/diff` 的彩色 diff。

### 更长期

9. **阶段 5** —— 颜色主题（由用户需求驱动）。
10. **阶段 4.2–4.6** —— 增强导航和命令。
11. **阶段 6** —— 全屏模式（重大工程，应在前几个阶段发布后再评估）。

## 4. 架构建议

### 阶段 0 之后的模块结构

```text
crates/rusty-claude-cli/src/
├── main.rs              # 入口，仅负责参数分发（约 100 行）
├── args.rs              # CLI 参数解析（整合现有两个解析器）
├── app.rs               # LiveCli 结构体、REPL 循环、轮次执行
├── format.rs            # 所有报告格式化（状态、成本、模型、权限等）
├── session_mgr.rs       # 会话 CRUD：创建、恢复、列表、切换、持久化
├── init.rs              # 仓库初始化（不变）
├── input.rs             # 行编辑器（不变，少量扩展）
├── render.rs            # TerminalRenderer、Spinner（扩展）
└── tui/
    ├── mod.rs           # TUI 模块根
    ├── status_bar.rs    # 固定在底部的状态行
    ├── tool_panel.rs    # 工具调用可视化（框、时间线、可折叠）
    ├── diff_view.rs     # 彩色 diff 渲染
    ├── pager.rs         # 用于长输出的内部 pager
    └── theme.rs         # 颜色主题定义与选择
```

### 关键设计原则

1. **保持内联 REPL 作为默认模式** —— 全屏 TUI 应该是可选的（`--tui` 标志）
2. **所有内容都应在不依赖终端的情况下可测试** —— 所有格式化函数都接收 `&mut impl Write`，绝不直接假定 stdout
3. **流式优先** —— 渲染应支持增量进行，而不是缓存整个响应
4. **终端控制统一使用 `crossterm`** —— 不要把原始 ANSI 转义码与 crossterm 混用（当前代码库在启动横幅中就这么做）
5. **重型依赖使用 feature gate** —— `ratatui` 应该放在 `full-tui` feature flag 后面

## 5. 风险评估

| 风险 | 缓解措施 |
|---|---|
| 重构期间破坏可用的 REPL | 阶段 0 只是纯结构调整，并以现有测试覆盖作为安全网 |
| 终端兼容性问题（tmux、SSH、Windows） | 依赖 crossterm 的抽象；在降级环境中测试 |
| 丰富渲染带来的性能回退 | 重构前后进行性能分析；始终保留快路径（原始流式输出） |
| 范围蔓延到阶段 6 | 在开始阶段 6 之前，先将阶段 0–3 作为一个一致的发布版本交付 |
| `app.rs` 与 `main.rs` 的混淆 | 阶段 0.2 通过移除遗留 `CliApp` 明确解决这个问题 |
